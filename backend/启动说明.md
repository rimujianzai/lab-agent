# 后端启动说明（backend/）

## 一、前提

1. **MySQL 已启动**，并且存在 `lab_agent` 库：
   ```bash
   mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS lab_agent DEFAULT CHARSET utf8mb4;"
   ```
2. **`.env` 里的连接串正确**（`backend/.env`）：
   ```
   DATABASE_URL=mysql+pymysql://root:你的密码@127.0.0.1:3306/lab_agent
   ```
3. **依赖装好**（必须包含 `cryptography`，原因见第四节）：
   ```bash
   ./.venv/Scripts/python.exe -m pip install -r requirements.txt
   ```

## 二、启动

在 `backend/` 目录下，二选一：

```bash
# 方式 A：推荐的启动脚本，会先检查端口、再启动
./.venv/Scripts/python.exe dev.py
./.venv/Scripts/python.exe dev.py 8010        # 换端口
./.venv/Scripts/python.exe dev.py --kill      # 先清理占用 8000 的残留进程，再启动

# 方式 B：原始命令（也可以正常用）
./.venv/Scripts/python.exe -m uvicorn app.main:app --reload
```

- 接口文档：<http://127.0.0.1:8000/docs>
- 健康检查：<http://127.0.0.1:8000/api/health>（能同时确认服务和数据库是否正常）

## 三、端口被占用（winerror 10048 / 请求连不上）

现象：`uvicorn` 报 `error while attempting to bind on address ... winerror 10048`，
或者 Apifox / 浏览器提示「无法连接到远程服务器」。

原因：Windows 上 `uvicorn --reload` 是用 `multiprocessing.spawn` 起子进程来跑服务的。
父进程被强杀（关掉终端、任务管理器结束进程）之后，**子进程会变成孤儿活下来**，
而它继承了监听用的 socket —— 端口一直放不掉，它还用**旧代码**继续响应请求。
更坑的是 `netstat` 里显示的是那个**已经不存在的父进程 PID**，
手动 `taskkill /PID xxx` 会提示「找不到进程」，让人完全摸不着头脑。

处理：

```bash
# 一条命令搞定
./.venv/Scripts/python.exe dev.py --kill
```

或者手动：先 `netstat -ano | findstr :8000` 拿到 PID，
如果提示进程不存在，就去任务管理器找那些 `spawn_main(parent_pid=...)` 的 Python 进程结束掉，
再重启。**下次别用「强制结束进程」的方式停服务，在终端里按 `Ctrl + C` 正常退出。**

## 四、为什么依赖里必须有 cryptography

MySQL 8 的默认认证插件是 `caching_sha2_password`。
PyMySQL 走这个插件时，**只有密码缓存没命中、需要走完整认证的那一次**才会用到
`cryptography` 包，否则直接抛：

```
RuntimeError: 'cryptography' package is required for sha256_password or caching_sha2_password auth methods
```

这个错误很隐蔽：时好时坏，看起来像「偶发的连不上数据库」。
（MySQL 重启、`FLUSH PRIVILEGES`、或换了新账号之后，缓存是冷的，就必然复现。）
以前建表写在模块顶层，这个异常会直接把 uvicorn 工作进程干掉，
于是又变成第三节那种「端口被占 + 请求连不上」的假死。现已改为在启动阶段建表，不会再出现。

## 五、登录接口

```
POST /api/auth/login
Content-Type: application/json

{"username": "aaa", "password": "123"}
```

响应统一是 `{code, message, data}`：`code=200` 成功，`code=400` 账号或密码错误。
